# LinkedIn Post Caption

I just finished building and deploying an end-to-end ML project: **Customer Churn Command Center**.

This started as a churn prediction pipeline, but I wanted it to feel closer to something a customer-success team could actually use, not just a notebook or a single prediction form.

What it includes:

- reproducible ML training pipeline
- model comparison and threshold tuning
- deployed Vercel dashboard
- single-customer scoring API
- batch CSV scoring API
- dynamic CSV column mapping
- live charts from uploaded data
- churn risk explanations
- revenue-at-risk prioritization
- next-best retention actions
- CRM/task CSV export
- drift and monitoring signals
- Postgres-ready database workflow
- workspace controls and optional API-token protection
- CI/CD with automated validation

The app can score Telco-style customer data, handle messy column names, explain risk drivers, and turn predictions into an action queue for retention teams.

Live demo: https://end-to-end-ml-pipeline.vercel.app  
Case study: https://end-to-end-ml-pipeline.vercel.app/case-study.html  
GitHub: https://github.com/janakjocee/End-to-End-ML-Pipeline

This project taught me a lot about the gap between “building a model” and “building a useful ML product”: data quality, deployment size, scoring APIs, business thresholds, monitoring, persistence, and making predictions actionable.

Would love feedback from ML engineers, data scientists, and product-minded builders.
